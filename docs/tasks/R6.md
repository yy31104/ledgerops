# R6：LedgerOps 侧的只读证据交换

采用原包的不可变文件、选定合成记录与来源、单向只读三项方向。当前项目仅交付LedgerOps协议、
可脱离项目运行的标准库读入器、黄金样例和兼容测试；不修改Chronicle，不声称另一项目已接入。
常规工程选择已由“直接完成剩余路线”授权，本切片不新增人工审批门槛。

第一项交付是明确选择提现/分录的manifest与records：保留账户/所有者不透明UUID、金额单位、
固定来源版本与摘要、原始例外和处置关系；排除数据库凭据、访问token、ACL、原始provider请求/
envelope和全部运维写能力。已有调查界面与独立读入器提供狭窄证据视图，无需新增修正入口。

第二项是独立兼容：v1.0黄金数据保持不变，v1.1明确增加format10来源和完整核验声明。
所有金额、序号、版本、水位用十进制字符串；拒绝未知主/次版本、单位、字段、重复身份或无效引用。
将读入器与两个数据文件复制出去后，Python -I -S应能在LedgerOps/数据库/支付商均不运行时复核。
以后账本变化不能改变已经发布的文件。

第三项是时间与权限边界：included-by-source-snapshot只说明源快照成员关系，不是任意历史截面查询。
本地recorded_at/received_at/resolved_at不能当支付商执行或数据库COMMIT时间；缺失的时间明确unknown。
当前结算引用只说明当时固定的run/pin/epoch/来源水位，不承诺仍是最新版本或reader pin仍存活。
非RR维护预览不进入本交换，避免宣称错误的快照语义。

验收包括100/80独立字面黄金样例、真实R5受控结算→财务源→选定交换→隔离标准库读入，
以及17MiB/超过10,000请求键的完整源和R4固定引用。保持完整源的不健康声明，不能因为选定的小部分
自洽就把整本账说成健康。无效版本/单位/身份/摘要/关系及超2^53整数各有负向或保真测试。

这份交换不证明完整账本A/B、历史人的权限、HMAC真实性、现实付款终局、Chronicle集成或个人掌握。
Hash是完整性检查，不是签名。只在本地提交；源参考包、lab、教程、tracker和Vault保持不动。
