## Deliverable and boundaries

Append migration 003 for a dedicated maintenance login, workspace projection epoch,
current freeze identity, durable freeze/resume metadata, immutable repair headers
and complete per-account before/after rows. Preserve 001/002 and purchase admission.
Do not introduce candidate tables, online rebuild, reservation lifecycle, production
reversal, HTTP/authentication adapter, external payout or R5 approval.

`ledgerops.db.maintenance` owns explicit READ COMMITTED READ WRITE transactions on
idle autocommit connections. Each operation takes the existing exclusive workspace
barrier before mode, metadata or lower locks and holds it through COMMIT. Set bounded
5s lock/10s statement timeouts. Propagate SQL/connection faults after rollback or as
outcome-unknown; no hidden retry or reconnect. Return only after acknowledged COMMIT.
The caller authenticates actor IDs and retains command IDs; UUIDs are audit labels,
not credentials. Raw owner/maintenance SQL remains a cooperating-protocol boundary.
Database freeze does not establish that external payments stopped.

## APIs

All IDs are canonical UUID text; reasons are exact nonempty UTF-8, at most 256 bytes,
without NUL. Reasons are not trimmed or normalized for replay.

| API | Contract |
|---|---|
| `freeze_workspace(conn, workspace_id, freeze_id, actor_id, reason)` | Drain shared holders; NORMAL→FROZEN with a durable freeze record. A different current freeze or RESTORE is refused. |
| `preview_rebuild(conn, workspace_id, freeze_id, output_root, *, code_revision, dirty=False)` | Verify the current freeze under the exclusive barrier, capture raw rows and A/B report, calculate complete account targets for eligible sources; publish captured evidence after DB transaction ends. Returns export_path/report/changes. |
| `apply_rebuild(conn, workspace_id, freeze_id, repair_id, actor_id, reason, preview_export_id)` | Re-read and verify current source under the exclusive barrier; independently SQL-fold entries, then atomically write projections/audit/epoch. No target-balance argument or preview-file input. Stays FROZEN. |
| `resume_workspace(conn, workspace_id, freeze_id, actor_id, reason)` | Fresh source/A/B/zero-reservation checks under the barrier, then explicit FROZEN→NORMAL and durable resume metadata. Healthy sources may resume without a no-op repair. |

Preview is inspectable evidence. It contains all accounts, including unchanged/idle
ones and the versions a subsequent repair would assign. Save the CLI's JSON report
if a separate human-readable record is wanted; its export UUID identifies the raw
snapshot from which the report was derived. A/B failure blocks application; projection
drift alone permits it. Nonzero reserved blocks application and resume, never gets
erased. No eligible target list is returned for unsupported/invalid sources.

`preview_export_id` is a caller-supplied audit reference. It is not an authenticated
preview receipt and is not used to calculate balances. The live source, current
freeze and fresh verifier decide application. The caller must inspect preview and
save the correct reference; the API does not prove a human read a report.

## Atomicity, identities and audit

The verifier's Python fold and repair's SQL aggregation are separate calculations.
SQL includes all accounts via LEFT JOIN, including missing idle projections. For
existing balances set debits/credits to recomputed cumulative totals, increment
version exactly once; insert missing rows at version 1 with reserved default 0.
Booked remains generated. Increment projection_epoch exactly once per committed
repair. Refuse cumulative/version/epoch exhaustion; never infer account versions
from entry counts. Tokens can later bind epoch plus account version.

Write an immutable header and one before/after audit row per account, including
missing-before and unchanged accounts. Header declares row count; deferred checks
reject incomplete logs and later appends. No UPDATE/DELETE on audit history.
Balance writes, audit rows, epoch and post-write independent verification all share
one transaction. COMMIT-time failure rolls everything back and preserves FROZEN.

Stable freeze/repair identity plus exact actor/reason/preview reference resolves
retries. A reused ID with different fields raises IDENTITY_CONFLICT. Same committed
repair ID returns its saved metadata and never increments anything twice. Closed
freeze/resume IDs return historical metadata without reopening or closing another
session; this is not a statement about the workspace's current mode. New actions
must match the current freeze. A failed/unknown commit must not be retried with a
new repair ID. Post-export/A/B and explicit resume are separate workflow steps;
resume performs its own fresh verification rather than trusting a stale report.

Database permissions keep maintenance outside financial history, account identity,
reserved writes, DDL, trigger disabling and app/migrator role membership. The role
can write projections and maintenance metadata, so the Python contract still
matters; privileges do not prove trusted maintenance SQL follows the repair protocol.
