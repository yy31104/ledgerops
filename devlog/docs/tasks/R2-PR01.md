## Interfaces and version boundary

Export format 1 has data.json and manifest.json. Data keys: format_version, workspace,
accounts, balances, operations, requests, journals, entries, snapshot_witness,
schema_versions, server_version. IDs are canonical UUID strings. Money is canonical
integer text. Version/line/status fields remain JSON integers, enabled remains boolean;
JSON bool must not pass integer validation. Bytes use payload_hex and payload_sha256
lowercase hex; timestamps use UTC text. No credentials or arbitrary connection data.

Manifest binds format/export/workspace IDs, full Git code revision and dirty flag,
data byte count and digest, exact row counts. These are exported-data integrity
hashes, not a SHA source inventory. Limits: at most 10,000 rows per table and 16 MiB for the complete data + manifest;
fail visibly before publication on overflow. Publish a complete fsynced sibling
temporary directory by rename to a fresh export UUID; never overwrite old exports.
Loader rejects temporary/symlink paths, unknown members/versions, duplicate JSON keys,
bad scope/shape/count/digest/length and partial packages. It checks bounded reads.

PR01 recognizes schema 001_foundation.sql and 002_export_reader.sql. A future financial
schema is rejected until the reader explicitly exports its new relations/capabilities;
never export old-table-only data while silently dropping reversals/repair metadata.
The general R2 format scope is extended in those later slices rather than pretending
nonexistent tables are already exported now.

Report exposes structure_ok, projection_ok, request_intent_ok, reservation_supported,
explicit issues and intent coverage. Repair eligibility requires valid structure and
retained intent plus supported zero reservations; **projection drift itself is the
repairable condition**, not a reason to forbid recomputing it. No hand manifest gate.
OPENING opaque legacy payloads receive structural/digest checks with disclosed funding-
intent limitations. Unknown/malformed purchase payloads fail B. Nonzero reserved is
reported as unsupported for repair; posted-balance checking still runs.

## Acceptance

1. Real service purchase→actual reader export→offline load/check passes A/B with
   no hand manifest. Idle accounts remain present. Original payload bytes survive.
2. Reader cannot INSERT/UPDATE/DELETE/DDL/escalate; application permissions and
   all existing R1 financial checks remain unchanged.
3. An observed concurrent writer commits between export table reads. The exported
   rows remain one coherent snapshot. Removing the isolation boundary must make the
   same expected-state assertion fail; no sleeps/timeout-as-success.
4. DB-valid missed balance update fails A while B can pass. Consistent M2 entries
   and balance fail B while A can pass. Missing idle projection is detected.
5. An extra test manifest detects when retained payload, entries and projection all
   consistently target the wrong merchant. Runtime checks disclose this trust limit.
6. Corrupt/truncated/extra-member/duplicate-key/wrong-scope/oversized bundles fail;
   filesystem publication fault leaves no completed-looking package.
7. Independent reversal model proves success-only uniqueness and rejected-result
   retention against the hand-calculated trace; its code imports no production helpers.
8. Existing R1 regression, new meaningful pure/real PostgreSQL tests, CLI smoke and
   build pass; actual evidence references Git base and delivered commit, no new
   SHA source list. One local implementation commit contains this slice.
