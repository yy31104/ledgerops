# Changelog

## 1.0.0

- Added a real `make demo-payout-crash` recording: provider commit, worker SIGKILL,
  recovery by original-key LOOKUP, one provider effect and one ledger settlement.
- Added `make verify-release`: isolated Compose SSE, real API restart, unchanged
  PostgreSQL draft and repeat-review identity checks; no operator action submission.
- Introduced a homepage-independent, 20-file operational corpus and migrated
  development labels/baseline without changing question wording or retrieval policy.
- Added an assistant entry on the homepage, six operating guides, a start page,
  internal references and a provider-paid/worker-crashed engineering article.
- Hardened action/authority refusals using a closed request grammar. A fresh
  frozen fake sample gets 36/40 routes and refuses all 20 action/injection cases;
  four unsupported topics still pass the scope boundary. No false refusal on six
  documentation controls. Historical failed samples remain available.
- Recorded 32 non-blind subscription answers: 27 complete, five incomplete. Retained
  per-call latency/provider token evidence, separate from dollar billing and budgets.
- Moved raw historical and current evaluation records to checksum-verified release
  attachments; source retains summaries, question sets, protocols and manifests.
- Prepared an optional Azure assistant initialization/service module and read-only
  smoke/cost-evidence tooling, with static validation. No cloud trial was performed.

### Known limits

This is a local synthetic-data reference, without a production deployment claim.
Finite refusal rules do not identify every unsupported topic or prove prompt-
injection safety. Citation checks establish provenance, not semantic correctness.
The v1-011 missing-context regression remains a strict expected failure. Three
historical BGE chunks exceeded 512 tokens; chunking and the 18 KB byte context policy
remain unchanged. ChatGPT subscription counters include SDK overhead and supply
no per-request dollar invoice. The 32-answer review is assistant-reviewed development
evidence, not a blind or independently human-labelled correctness estimate.
Azure runtime behavior and cost remain unmeasured; extended lifecycle lint warnings
are retained for the explicitly disposable rehearsal, as documented in its guide.
